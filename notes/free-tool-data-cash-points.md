# 無料ツール × 一次データ × キャッシュポイント（上流の設計）

作成日: 2026-10-02
前提: `blue-collar-offer-and-referral-design.md` の続き。
論点: 現場企業に請求・事務周りを整理する自社ツールを無料で提供し、経営者の時間を返すことをコンセプトに顧客チャネルを広げる。では、どこで稼ぐか。一次データの価値をどう現金に変えるか。

---

## 0. 結論

**ソフトでは稼がない。「流れ」に乗って稼ぐ。**
無料ツールはデータの取得面であり、信頼の入口。稼ぐ場所は、そのデータが流れを握った先にある。

```
無料ツール（出面・日報・見積・請求・AI受付）
   ↓ 日次の一次データ（人・現場・金）
キャッシュポイント1  金の流れ    早期入金、職人への前払い、支払い代行、保険     ← 最大。最初に取る
キャッシュポイント2  物の流れ    資材の共同購買、機械レンタル                   ← 2番目
キャッシュポイント3  仕事と人の流れ  顧客網での仕事の融通、人の融通、採用        ← 網ができてから
キャッシュポイント4  会社そのもの   承継、資本参加                             ← 最終
```

SquareやToastやShopifyが「無料・安価なソフト → 決済 → 融資」で稼いだのと同じ構造を、日本の現場産業に当てはめる。
違いは、日本の現場産業では決済より **資金繰りの歪み** が大きいこと。だから金融が最初に来る。

---

## 1. なぜ「ソフトで稼がない」のか

- 事務ツールは freee、マネーフォワード、ANDPAD などが既にいる。月額数万円の席数課金で戦うと、彼らと同じ土俵で、価格はゼロに向かう（`ai-organization-2027-market.md` 3.3）。
- 現場の社長は「ソフト代」を嫌う。「金を回すところ」で払うのは慣れている（手形、ファクタリング、問屋の掛け）。
- 無料にすると導入の摩擦が消え、紹介が起きやすい。「タダで事務が楽になる」は社長が仲間に言いやすい。
- ただし「なんで無料？」に正直に答える必要がある。「うちは金と仕事を回すところで稼ぐ。ツールは無料でいい」。義理の文化では、隠すと終わる。

---

## 2. 無料ツールは何を取るか（データ設計が全て）

### 2.1 「日次」で触られるものを核にする
請求は月1回。月1回では文脈が古くなる。日次で触られるのは **出面（誰がどの現場に何日入ったか）と日報** 。
出面は給与と請求の両方の元になる。これを核にすると、人・現場・金の全てが日次で揃う。

| 機能 | 取れるデータ | 流れへの接続 |
|---|---|---|
| 出面・日報 | 誰が、どの現場に、何日、何をしたか | 職人前払い、採用・定着、仕事の融通 |
| 見積 | 単価、原価、工期、顧客 | 単価ベンチマーク、値上げ支援、共同購買 |
| 請求・入金 | 請求額、相手先、支払サイト、入金実績 | 早期入金の与信、元請け依存度 |
| 外注・仕入 | 外注先、資材、価格 | 共同購買、人の融通 |
| AI受付（取りこぼしゼロ） | 問い合わせ、応募、対応履歴 | 受注・採用の流れ |

### 2.2 業種特化で、小さく
freee や ANDPAD の汎用さと戦わない。1業種の「出面→給与→請求」の型だけを、その業種の言葉で、スマホで、現場で入れられるものにする。
AIで入力の手間を消す（写真・音声・LINEから出面が立つ）。これが「無料でも使い続ける」理由になる。

---

## 3. キャッシュポイント1: 金の流れ（最初に取る）

### 3.1 現場産業の資金繰りの歪み
```
元請けからの入金   月末締め、翌々月払い、手形もある   → 遅い
職人への支払い     月末、または日払い・週払い         → 早い
資材の支払い       当月〜翌月                        → 早い
```
社長はこの差を自分の金と借入で埋めている。これが「人を大切にしたいのに給料が遅れる」「仕事を取っても金が回らない」の正体。

### 3.2 商品
| 商品 | 内容 | 収益 | データの役割 |
|---|---|---|---|
| 早期入金（請求書の早期資金化） | 元請けへの請求を、入金前に資金化 | 請求額の1〜3% | 請求・入金の実績が与信そのもの。銀行にはないデータ |
| 職人への前払い・日払い | 出面データに基づいて、働いた分を即日払える | 1回あたり数%、または会社負担の月額 | 出面がそのまま支払根拠になる。採用と定着にも直結する |
| 支払い代行・カード | 資材・外注の支払いを立て替え、サイトを延ばす | 手数料、カード決済の取り分 | 仕入データ |
| 保険 | 工事保険、労災上乗せ、賠償 | 代理店手数料 | 現場・人のデータで適正な保険が選べる |

### 3.3 やり方
- **最初は自分で金融をやらない。** 貸金業、ファクタリングの規制、資本、与信リスクがある。
- 既存の事業者（請求書早期資金化、給与前払いサービス）と提携し、自分は **データとチャネル** を提供して紹介料・データ連携料を取る。
- 顧客が50〜100社になり、データで与信精度が出せると分かった段階で、内製化か、出資を受けて自社でやるかを決める。
- 社長への見せ方は「金融商品」ではなく「職人に給料を遅らせずに済む」「元請けの支払いを待たずに次の現場に入れる」。大義と義理に接続する。

---

## 4. キャッシュポイント2: 物の流れ

- 顧客の見積・仕入データから「何を、どこから、いくらで」買っているかが分かる。
- 同業50社の購買をまとめると、問屋・メーカーへの交渉力が出る。
- **共同購買**: まとめて安く買い、差額の一部を取る。または問屋から販売奨励金を受ける。
- 社長への見せ方は「資材が安くなる」。単純で強い。
- 機械・車両のレンタルも同じ構造。

---

## 5. キャッシュポイント3: 仕事と人の流れ（網ができてから）

- 出面と工期のデータで、どの会社がいつ空いているか、どの現場が人手不足かが分かる。
- 顧客網の中で仕事と人を融通し、融通された仕事の数%を取る。
- 施主からの直接問い合わせ（AI受付で取ったもの）を網の中の適切な業種に回し、紹介料を取る。
- 採用は、求人媒体の原稿・掲載を有料にできるが、ここは金額が小さい。網の価値の方が大きい。

---

## 6. キャッシュポイント4: 会社そのもの

- 数百社の「本当の収益性、顧客基盤、工期、職人の定着」をデータで持っている状態は、承継市場で誰も持っていない位置。
- 後継者不在の顧客を、自分が承継する、または承継したい人と組んで資本参加する。
- 承継後の運営は、無料ツールで既に整っている事務の上にAI組織を乗せるだけ。承継コストが極端に低い。
- `value-sources-and-what-i-would-build.md` の承継事業は、この無料ツール戦略の終着点として位置づけられる。

---

## 7. 一次データの価値の正体

データを「売る」のではない。データは4つの形で現金になる。

| 形 | 内容 | 誰にも真似できない理由 |
|---|---|---|
| 与信 | 請求・入金・出面の実績で、銀行より正確に貸せる | 銀行は決算書しか見ない。日次の実績は自分しか持たない |
| ベンチマーク | 業種・地域の単価、原価、工期、支払サイトの相場 | 社長に「あなたの単価は地域平均より低い」と言える。値上げ支援は大義そのもの |
| 選別 | どの会社が承継に値するか、どの社長が網に合うか | 外からは見えない |
| AI組織の文脈 | 承継後、またはAI組織化の際、会社を運営するための全文脈が既にある | Addnessで培った組織OSの知見がここで効く |

**社長のデータを第三者に売ることはしない。** 匿名化したベンチマークは別だが、元請けやメーカーに個社のデータを渡した瞬間、義理の文化では終わる。データは「社長のために使う」「流れを握るために使う」の2つだけ。

## 8. 1社あたりの経済性（仮置き。業種で大きく変わる）

前提: 年商2億円、職人10人、資材・外注が年商の30%。

| 収益源 | 仮定 | 年間収益/社 |
|---|---|---|
| 早期入金 | 請求2億のうち20%を利用、手数料1.5% | 60万円 |
| 職人前払い | 10人 × 月5万円 × 手数料3% | 18万円 |
| 共同購買 | 資材6,000万円 × 2%の差益・奨励金 | 120万円 |
| 保険 | 代理店手数料 | 10〜20万円 |
| 仕事の融通 | 融通500万円 × 5% | 25万円 |
| 合計 | | **約230〜250万円** |

比較: ソフトの月額課金で取れるのは、せいぜい月2〜5万円、年24〜60万円。
流れに乗ると、ソフトの4〜10倍になる。しかも社長は「ソフト代」ではなく「金が回る」「資材が安い」として払うので、解約の理由が消える。

100社で2億円超、300社で7億円超の規模感。ただし共同購買の2%は交渉力次第で、最初は出ない。現実的には早期入金と前払いから始まる。

## 9. 順番（何から始めるか）

| 時期 | やること | 目的 |
|---|---|---|
| 0〜6ヶ月 | 1業種・1地域で、無料ツール（出面・請求・AI受付）を10〜20社に入れる | データと信頼。この間の収入は「取りこぼしゼロ」の有料化か、過渡期の導入支援で賄う |
| 3〜9ヶ月 | 早期入金・前払いの事業者と提携し、無料ツールから申し込める状態にする | キャッシュポイント1の立ち上げ。紹介料から |
| 6〜12ヶ月 | 仕入データが溜まったら、問屋・メーカーと共同購買の交渉 | キャッシュポイント2 |
| 12ヶ月〜 | 50社を超えたら、網での仕事と人の融通を仕組み化 | キャッシュポイント3 |
| 18ヶ月〜 | 与信精度が出ていれば金融の内製化を検討。承継の1社目 | キャッシュポイント1の深化、4の開始 |

## 10. リスクと落とし穴

| リスク | 対処 |
|---|---|
| 金融の規制（貸金業法、ファクタリングの規制動向、建設業法・下請法の支払サイト規制） | 最初は提携。内製化は専門家と設計。2社間ファクタリングには近づかない |
| 元請けと敵対する構図になる | 元請けを敵にしない。「下請けの資金繰りが安定すると元請けの工程も安定する」と位置づける |
| 無料ツールのサポート負担 | AIで一次対応。業種を絞って機能を絞る。汎用化しない |
| freee・ANDPAD などとの競合 | 戦わない。彼らは事務の汎用ツール。こちらは1業種の出面と金の流れ。連携してもいい |
| 「無料」が怪しまれる | 正直に言う。「金を回すところで稼ぐ」。隠すと義理の文化では終わる |
| 共同購買の交渉力が出る前に約束する | 社数が揃うまで言わない |
| データを第三者に売りたくなる | 売らない。流れを握るためだけに使う |

---

## 11. 一言で

無料ツールは「事務を楽にする道具」ではなく、人・現場・金の日次データを取る面。
稼ぐのは金の流れ（早期入金・前払い）、物の流れ（共同購買）、仕事と人の流れ（網）、そして会社そのもの（承継）。
ソフトでは稼がない。流れに乗る。データは売らず、与信・相場・選別・AI組織の文脈として使う。

## 12. 具体例: 「金の流れで稼ぐ」を1社で追う

### 架空の会社
田中設備（管工事）。年商2億、職人10人。元請けA社の仕事が中心。

### ある月の金の動き（うちが何もしない場合）
```
5/1〜5/31  A社の現場で工事。職人10人 × 20日。
5/31      A社に 500万円 を請求。支払条件は「月末締め・翌々月末払い」→ 入金は 7/31。
6/25      職人10人の給料 300万円 を払う。
6/30      資材屋に 100万円 を払う。
7/31      A社から 500万円 入金。
```
社長は 6/25〜7/31 の間、**400万円を自分で立て替えている。** 手元にないなら、銀行に借りるか、仕事を断るか、給料を遅らせる。これが毎月続く。

### うちが入った場合（早期入金）
```
5/31  社長がうちの無料ツールで A社宛の請求書 500万円 を作る。
      その画面に「この請求、今すぐ現金にしますか？ 手数料 1.5%（7.5万円）」と出る。
6/2   「はい」を押す。
6/3   田中設備の口座に 492.5万円 が振り込まれる。
7/31  A社の 500万円 は、うち（または提携先）の口座に入る。
```
**差額の 7.5万円 がうちの売上。** 社長は「ソフト代」を1円も払っていない。
社長から見ると、7.5万円で400万円の立替から解放され、給料を遅らせずに済み、銀行に書類を出す必要もない。手形割引と同じ感覚で、もっと速くて楽。

### 誰が 492.5万円 を出すか
- **最初**: 提携先（請求書の早期資金化をやっている会社）が出す。うちは「申込みの入口」と「データ」を提供し、手数料のうち 0.5% 前後（2.5万円）を受け取る。
- **後で**: 自社の資金（出資や銀行の与信枠）で出す。1.5%（7.5万円）が丸ごと残る。
  ただし100社分を常時立て替えるには数億円の枠が要る。だから最初は提携。

### なぜ「データ」で勝てるか
提携先や銀行は、A社が本当に払う会社か、田中設備が本当に工事をしたか、分からない。だから手数料が高く（相場2〜9%）、審査に日数がかかる。
うちは分かる。
- 出面データ: 5月にA社の現場に職人10人が20日入った事実がある。
- 請求・入金の履歴: A社は過去24ヶ月、一度も遅れず払っている。
だから **安く、速く、貸し倒れが少ない。** 手数料1.5%でも成り立つ。銀行は去年の決算書しか見ていない。これが「一次データが価値になる」の正体。

### もう一つの流れ（職人への前払い）
```
6/10  職人の佐藤さんが「今月もう15日働いた分、今欲しい」（子どもの学費）。
      ツールから申請。出面データが「15日 × 日当1.8万円 = 27万円 働いた」ことを証明している。
6/11  佐藤さんの口座に 27万円 − 手数料3%（8,100円）= 26.2万円 が振り込まれる。
6/25  給料日に、会社の給与から 27万円 を相殺。
```
**8,100円 がうちの売上。** 手数料は職人負担でも、会社が福利厚生として負担してもいい。
社長から見ると「職人に日払いで応えられる会社」になり、採用と定着に効く。これは「人を大切にする」価値観そのもの。

### 田中設備1社から、毎月いくら立つか
| 流れ | 仮定 | 月の売上 |
|---|---|---|
| 早期入金 | 月の請求1,500万円のうち3割（450万円）を利用 × 1.5% | 6.75万円 |
| 職人前払い | 月10件 × 5万円 × 3% | 1.5万円 |
| 資材支払いの立替（カード・後払い） | 月100万円 × 1.5% | 1.5万円 |
| 合計 | | **約10万円/月、約120万円/年** |

ソフトの月額課金なら2〜5万円/月で、しかも社長は払いたがらない。
流れなら10万円/月が、社長が「助かった」と感じながら払われる。

### 「流れで稼ぐ」の本質
- 月額課金は「使っても使わなくても同じ額」。流れ課金は「金が動いた分だけ、その数%」。
- 動く金の規模は年商（2億円）。ソフトに払える金の規模は年数十万円。**桁が違う。**
- 請求書を作る瞬間、給料を払う瞬間、資材を買う瞬間にボタンがある。社長は他を探しに行かない。これが「埋め込まれている」ことの価値。

### 損するケース
A社が倒産すると、立て替えた500万円が戻らない。だから、
- 最初は提携先がリスクを持つ。
- 自社でやる時は、データで「払う元請け」だけに絞る。
- 元請けに通知する形（3社間）か、保証をつける。2社間ファクタリングは法的に危ういので近づかない。
