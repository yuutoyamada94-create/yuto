# 背骨の設計: 配車 → 日報 → 請求 → 入金（スプレッドシートで）

作成日: 2026-10-03
前提: `daily-report-design.md`、`data-to-profit-haulage.md` の続き。
提案された案: 日報の効率化 → 請求書まで一気通貫 → スプレッドシートでデータ管理 → 現場の負担軽減。これが最大インパクトか。

---

## 0. 評価

方向は正しい。日報→請求の一気通貫が背骨で、スプレッドシートが道具として正しい。
直すのは3点。
1. **背骨の両端を足す。** 日報の前に「配車表（予定）」、請求の後に「入金」。予定が無いと漏れが検知できず、入金が無いと金が締まらない。
2. **受入（処分場）の背骨を並走させる。** この会社では受入が利益の柱で、しかも自社発行の伝票なので運搬より簡単。IT的な発想で「日報」だけに寄ると、一番大きな金を落とす。
3. **「現場の負担軽減」は売り文句ではなく制約。** 運転手は今も負担を感じていない（書いていないから）。軽くなるのは事務と社長。売るのは「締めてから3日で請求が出る」「漏れが取れる」「3枚の一覧」という出力。

## 1. 背骨（運搬）

```
配車表（予定）  →  日報（実績）  →  請求（得意先別・現場別・書式別）  →  入金（消込・未入金）
 配車担当の紙を      伝票写真＋位置      月末に下書き、人が確認          銀行明細と突合
 夕方に転記          から自動生成        元請けの書式に流し込む           未入金は社長に通知
```

| 節 | 入力元 | こちらがやること | 出力 |
|---|---|---|---|
| 配車表 | 配車担当の紙・口頭・LINE | 毎夕、転記（最初は人、のちにAI） | 誰が・どの車で・どの現場に・何往復予定・処分先 |
| 日報 | 伝票写真（LINE）、位置（デジタコ／スマホ）、自社処分場の受入票 | 自動生成、予定との差分を本人に確認 | 1往復ごとの実績、待機、拘束 |
| 請求 | 日報、単価マスタ（契約形態・単価・待機条件） | 月末に下書き、人が確認、元請け書式へ | 請求書、請求一覧、待機料 |
| 入金 | 銀行明細 | 消込、未入金の通知 | 入金サイト、未回収 |

### なぜ配車表を足すか
日報だけでは「漏れ」が分からない。「3往復の予定で伝票が2枚」は、予定があって初めて言える。
配車表は配車担当の縄張りだが、**転記するだけ** なら触っていない。判断は変えない。

### なぜ入金を足すか
請求が早くなっても、入金が締まらなければ社長の金は変わらない。
消込と未入金の通知で「2ヶ月立替」が見える。これが後の早期入金（提携）の導線になる。

## 2. 背骨（受入・処分場）

```
受入票（自社発行）  →  受入台帳（業者別・土質別・時間帯別）  →  請求／現金  →  残容量
```

| 節 | 入力元 | 出力 |
|---|---|---|
| 受入票 | 処分場の受付が発行（紙かレジ） | 業者、車格、土質、量、時刻、単価 |
| 受入台帳 | 受入票の集計 | 日別台数、業者別の量と単価、土質別の構成、時間帯別の混み |
| 請求／現金 | 掛けの業者は月末請求、現金の業者はその場 | 受入売上、未回収 |
| 残容量 | 受入量の累計と測量 | 残り月数 |

受入票は自社で出しているので、**運転手に何も頼まずに全件取れる。** 運搬より先に完成する。
そしてここから出る「土質別単価と残容量」が、社長の最大の判断（穴の値決め）に直結する。

---

## 3. スプレッドシートの設計: 「1往復1行」

全ての元は **1往復＝1行** 。ここから日報も請求も利益も派生する。

| シート | 1行の単位 | 主な列 |
|---|---|---|
| マスタ_得意先 | 得意先×支店 | 名称、書式、締め日、支払サイト、担当 |
| マスタ_現場 | 現場 | 得意先、住所、契約形態（車建て／m3建て）、単価、待機条件、指定処分先、期間 |
| マスタ_車両 | 車 | 車格、車番、デジタコ有無、リース・償却 |
| マスタ_運転手 | 人 | 日当、免許、入社日 |
| マスタ_処分先 | 処分場 | 受入単価（土質別）、受入時間、距離 |
| 配車 | 日×車 | 運転手、現場、予定往復、処分先、備考 |
| **往復（実績）** | **1往復** | 日、車、運転手、現場、処分先、積込時刻、受入時刻、待機（現場／処分場）、伝票画像、土質、量 |
| 日報（ビュー） | 日×運転手 | 往復数、待機合計、拘束時間、OK有無（往復シートから集計） |
| 受入 | 1台（持込） | 日時、業者、車格、土質、量、単価、現金／掛け |
| 請求 | 得意先×現場×月 | 車建て日数、m3、待機時間、金額、書式、発送日 |
| 入金 | 入金1件 | 日、得意先、金額、消込先 |

### 3枚の一覧は全部ここから出る
- 車両別・得意先別・現場別の「1台1日の利益」 ← 往復 × 現場マスタ（単価）× 車両・運転手（原価）
- 処分場の「土質別・業者別・時間帯別の受入」と残容量 ← 受入
- 運転手別の「稼働・拘束・売上」 ← 往復 × 運転手

### スプレッドシートで正しい理由
- 事務と社長が見られる。壊れても戻せる。
- 元請けの書式（Excel）に流し込みやすい。
- 作る前に売れる。1社目はこれで十分。
- 裏に構造化した保存（往復の行）を最初から置いておけば、5社・10社になった時にDBへ移せる。画面はシートのまま。

## 4. ITの癖で間違えやすいところ

| 癖 | ここでの正解 |
|---|---|
| アプリを作りたくなる | 作らない。LINE＋シート＋AIの読み取りで足りる。入力画面を作った瞬間、誰も入力しない |
| 正規化しすぎる | 事務が読めるシートにする。1往復1行だけ守れば、あとは平ら でいい |
| 請求を全自動にしたくなる | 下書きまで。金に関わる出力は人が見る。1ヶ月目は特に |
| 日報の「形式」を変えたくなる | 変えない。紙はそのまま。写真と位置から裏で作る |
| 現場の負担軽減を前に出す | 出さない。運転手は負担を感じていない。制約として守るだけ |
| 「効率化」と言う | 言わない。「締めて3日で請求」「漏れ○万円」「3枚の紙」と言う |
| 配車を最初に触る | 最後。転記だけ |
| 受入を忘れる | この会社では受入が先。自社発行で全件取れる |

---

## 5. 社長に見せる言い方

「毎日の伝票を写真で送ってもらうだけで、月末に請求書が3日で出ます。待機料の取り漏れも出ます。穴の方は、何の土が何台、いくらで入ったかが毎月1枚で分かります。社長は紙を1枚見て決めるだけです。」

「効率化」「一気通貫」「データ管理」は、こちらの内部の言葉。社長には使わない。

---

## 6. 一言で

背骨は「配車→日報→請求→入金」と「受入票→台帳→現金→残容量」の2本。
1往復1行のシートが全ての元。
現場の負担軽減は制約、売るのは出力。
