# AI事務員のワークフロー試作（ダンプ＋処分場会社向け）

`notes/spine-design-dispatch-to-cash.md` と `notes/daily-report-design.md` の設計を、動く形にしたもの。
配車表 → 伝票（写真） → 往復（1往復1行） → 日報 → 請求 → 入金、と、受入票 → 受入台帳 → 残容量 → 社長に渡す3枚。

```
workflow/
├─ make_sample_data.py   サンプルデータ生成（5営業日・6台・処分場1つ。漏れを意図的に仕込んである）
├─ extract_slip.py       伝票の写真 → 1行（Claude の画像読み取り＋構造化出力。APIキーがある環境で使う）
├─ pipeline.py           本体。標準ライブラリのみ。`python3 pipeline.py`
├─ data/                 入力CSV（マスタ、配車表、伝票、位置、受入）
└─ out/                  出力（往復、漏れと催促文、日報と確認文、請求下書き、社長の3枚、サマリ）
```

## 流れ

| 段 | 入力 | AI／機械がやること | 人がやること | 出力 |
|---|---|---|---|---|
| 配車表 | 配車担当の紙・口頭・LINE | 転記（最初は人、のちにAI） | 配車の判断（変えない） | `data/dispatch.csv` |
| 伝票 | 運転手がLINEで送る写真 | `extract_slip.py` が読み取り、土質・立米・時刻・ピンボケ判定 | 読めない写真を見る | `data/slips.csv` |
| 位置 | デジタコ／会社スマホ | 到着・出発の時刻、停止時間＝待機 | なし | `data/location_events.csv` |
| 往復 | 上の3つ | 位置を骨格に、伝票を時刻で貼る。1往復1行 | なし | `out/trips.csv` |
| 漏れ | 予定と実績の差 | 伝票なし・予定未達・超過・待機を検知し、**その日の16〜17時に本人へ催促文** | 送る（または自動送信） | `out/gaps.csv` `out/line_gaps.txt` |
| 日報 | 往復 | 運転手ごとに自動生成、夕方「OK?」を送る | 運転手はOKを押すだけ | `out/daily_reports.csv` `out/line_daily.txt` |
| 請求 | 往復＋現場マスタ | 車建て／立米建てを判定、待機料（30分切上）、外部処分費の実費を計上 | **人が確認してから元請け書式へ** | `out/invoices.csv` `out/invoice_*.txt` |
| 受入 | 処分場の受入票（自社発行） | 土質別・業者別・時間帯別、残容量と残り月数 | なし | `out/owner_2_intake.md` |
| 3枚 | 全部 | 1台1日の利益／穴の受入／運転手別の稼働、と**社長に出す二択** | 社長が決める | `out/owner_1_*.md` `owner_2_*.md` `owner_3_*.md` |

## 動かす

```bash
python3 make_sample_data.py   # data/ を生成
python3 pipeline.py           # out/ を生成し、サマリを表示
```

伝票の写真を実際に読むには（任意）:

```bash
pip install anthropic
export ANTHROPIC_API_KEY=...
python3 extract_slip.py photos/*.jpg > data/slips_from_photos.csv
```

## サンプルに仕込んだ「漏れ」と、検知される様子

| 仕込み | 検知 |
|---|---|
| 10/01 V2 の3往復目、現場の受領伝票が無い（受入票はある） | `受領伝票なし` → 16:00に佐藤さんへ催促文 |
| 10/02 V3 の3往復目、伝票が両方無い。位置だけが往復を示す | `受領伝票なし` `受入票なし` → 鈴木さんへ催促文。往復は位置から計上され、請求漏れにならない |
| 09/30 V4 が現場で95分待たされたが申告していない | `待機（請求対象）` → 日報に自動記載、待機料に反映、本人に「合ってます？」 |
| 09/29 V2 が待機で2往復しかできなかった | `予定未達` ＋ `待機` → 配車担当へ。本人は責められない |
| 10/02 V5 が5往復（予定4） | `予定超過` → 請求に反映 |

## 社長の3枚で見えること（サンプル）

- 車建ての港北A現場は1日4回転。元請けが得をしている。立米建てか単価交渉の根拠。
- 立米建ての鶴見B現場は待機が平均37分。5日で待機料67,500円が請求できる（今まで請求していなかった分）。
- 処分場は第1種（安い土）が台数の過半で残容量を使い、残り約4ヶ月。9時台に集中。→ 二択を社長に。
- 高橋・佐藤は待機が多い。本人の責任ではなく、待機手当の対象。

## 設計の約束（コードに反映している）

- 運転手が新しくやるのは「伝票の写真を送る」と「夕方OKを押す」だけ。文字は書かない。
- 配車の判断、単価、受入可否は人。機械は聞き取り・記録・集計・催促。
- 金に関わる出力（請求書、待機料）は `needs_human_check=yes`。人が見てから出す。
- 漏れは翌日に聞かない。その日の16〜17時に聞く。
- 自社処分場の受入票は自社発行なので、運転手が何も送らなくても往復が確定する。

## 次にやること（実データが来たら）

1. `data/` のマスタを本物に置き換える（得意先、現場の契約形態と単価、車両、運転手、処分場の単価と残容量）。
2. 過去3ヶ月の紙の伝票を写真に撮り、`extract_slip.py` で `slips.csv` を作る。配車表は転記。
3. `pipeline.py` を回し、3枚の粗い版を出して、社長・専務に見せる。
4. 元請けの請求書式（Excel）への流し込みを `invoices.csv` から作る。
5. 1社で回ったら、`data/` の形を変えずに2社目へ。業種の型になる。
